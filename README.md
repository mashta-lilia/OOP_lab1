# Електронна таблиця — лабораторна робота №1

**Дисципліна:** Об'єктно-орієнтоване програмування, КНУ імені Тараса Шевченка, ФКНК
**Виконала:** Лілія Машта, група К-27
**Рівень:** середній (другий), **варіант 8**

Програма для роботи з електронними таблицями: аналіз та обчислення виразів.
У клітинки записуються вирази з цілими числами довільної довжини, дужками,
посиланнями на інші клітинки та операціями варіанта 8. Програма спочатку
перевіряє синтаксис виразу (з позицією помилки), а потім обчислює значення.

## Можливості

- Введення виразів у клітинки та у рядок формули.
- Режими відображення **ВИРАЗ / ЗНАЧЕННЯ**.
- Автоматичний перерахунок залежних клітинок у правильному порядку.
- Циклічні посилання не приймаються.
- Вставлення і видалення будь-якого рядка чи стовпчика (у місці вибраної клітинки);
  посилання у виразах зсуваються автоматично, а посилання на видалені клітинки
  стають `#ПОСИЛАННЯ!` (помилка «Посилання на видалену клітинку»).
- Нова таблиця, відкриття та збереження файлів (JSON) на локальному диску.
- Головне меню і кнопки, що його дублюють; гарячі клавіші Ctrl+N / Ctrl+O / Ctrl+S.
- Сторінка «Довідка» та вікно «Про програму». Увесь інтерфейс — українською.
- Перед створенням, відкриттям або закриттям програма пропонує зберегти зміни.

## Синтаксис виразів (варіант 8)

| Елемент | Приклад |
|---|---|
| цілі числа довільної довжини | `12345678901234567890` |
| посилання на клітинку (латинські літери + номер рядка; `a1` = `A1`) | `A1`, `B12`, `AA3` |
| дужки | `(2+3)*4` |
| бінарні `+ - * /` (`/` — ділення націло з округленням до нуля) | `7/2 = 3`, `-7/2 = -3` |
| унарні `+ -` | `-A1`, `2*-3` |
| піднесення до степеня `^` | `2^10` |
| `inc(x)` = x + 1, `dec(x)` = x − 1 | `inc(A1)` |

**Пріоритет операцій** (від найсильнішої):
1. дужки, `inc`, `dec`;
2. унарні `+ -`: `-2^2 = (-2)^2 = 4` (як у таблиці пріоритетів з лекції);
3. `^` — правоасоціативний: `2^3^2 = 2^9 = 512`;
4. `* /`;
5. бінарні `+ -`.

**Додаткові правила:**
- Можна почати вираз зі знака `=`, як в Excel.
- Порожня клітинка дорівнює 0.

**Помилки:**
- синтаксична помилка з позицією;
- ділення на 0;
- від'ємний показник степеня;
- показник степеня більший за 10000;
- результат більший за 100 000 біт;
- посилання на неіснуючу клітинку або на клітинку з помилкою.

**Обмеження:**
- таблиця — до 200 × 200;
- вираз — до 500 символів.

## Структура рішення

```
LabCalculator.slnx
├── LabCalculator.Core     — уся логіка (бібліотека класів, нічого не знає про інтерфейс)
│   ├── Grammar/           — граматика ANTLR4 (LabCalculator.g4)
│   ├── Parsing/           — ExpressionParser, Evaluator (шаблон Visitor), ThrowExceptionErrorListener,
│   │                        ReferenceShifter (зсув посилань при вставці/видаленні рядків),
│   │                        Generated/ — код від ANTLR
│   ├── Models/            — Table, Cell, CellAddress, ICellValueProvider, EvaluationException
│   ├── Dependencies/      — DependencyGraph (циклічні посилання, порядок перерахунку)
│   ├── Storage/           — ITableStorage, JsonTableStorage (шаблон Strategy)
│   └── TableController.cs — контролер (шаблон Controller з GRASP)
├── LabCalculator.App      — інтерфейс .NET MAUI (MainPage, HelpPage, TableFiles)
├── LabCalculator.Tests    — unit-тести (xUnit)
├── samples/               — тестові файли таблиць з очікуваними значеннями
├── docs/uml/              — діаграми прецедентів, класів і послідовності (PlantUML + PNG/SVG)
├── experiments/           — експерименти (порівняння альтернативних реалізацій)
└── tools/                 — скрипти перегенерації парсера з граматики
```

Інтерфейс лише передає дії користувача контролеру, а вся логіка лежить у
`LabCalculator.Core`. Тому в обробниках кнопок немає бізнес-логіки
(антишаблон «магічна кнопка» відсутній).

## Як запустити

1. Visual Studio 2022 або новіша з компонентом **.NET Multi-platform App UI development**.
2. Відкрити `LabCalculator.slnx`.
3. Обрати проєкт `LabCalculator.App` і ціль **Windows Machine**, натиснути ▶.

Java та ANTLR для збирання **не потрібні**: C#-парсер уже згенеровано і він
лежить у `LabCalculator.Core/Parsing/Generated`. Якщо змінити граматику,
парсер перегенерують скрипти (потрібна Java 11+):

```powershell
powershell -ExecutionPolicy Bypass -File tools/generate-parser.ps1   # Windows
```
```sh
sh tools/generate-parser.sh                                          # Linux / macOS
```

## Тести

- **Visual Studio:** Test → Run All Tests.
- **Командний рядок:** `dotnet test LabCalculator.Tests`.

10 unit-тестів (xUnit) у файлі `LabCalculator.Tests/LabCalculatorTests.cs`.
Залежності замінено моками (**Moq**):
- `Mock<ICellValueProvider>` замість таблиці — обчислювач тестується окремо;
- `Mock<ITableStorage>` замість файлів — контролер тестується без диска.

| Клас | Що перевіряють тести |
|---|---|
| `ExpressionParser` | розбір коректного виразу й пошук посилань; синтаксична помилка з позицією |
| `Evaluator` | пріоритет операцій варіанта 8 і великі числа; ділення на 0; читання клітинки через мок (`Verify`); передавання помилки з мока |
| `TableController` | перерахунок залежних клітинок; відхилення циклічного посилання; видалення рядка зсуває посилання і дає `#ПОСИЛАННЯ!`; відкриття і збереження через мок сховища (`Verify`) |


### 1. `BigInteger` замість `double`

Те саме обчислення у програмі (`BigInteger`) і в типі `double`:

| Вираз | Програма (`BigInteger`) | `double` | Збігається |
|---|---|---|---|
| `2^53 + 1` | 9007199254740993 | 9007199254740992 | ні |
| `2^64 - 1` | 18446744073709551615 | 18446744073709551616 | ні |
| `99999999999999999999 + 1` | 100000000000000000000 | 100000000000000000000 | так |
| `3^40` | 12157665459056928801 | 12157665459056928768 | ні |
| `123456789 * 987654321 * 111` | 13534522053502514859 | 13534522053502515200 | ні |

`double` зберігає лише ~15–17 значущих цифр, тому вже після 2^53 він помиляється
у 4 випадках з 5 (а в третьому відповідь збіглася випадково — обидва числа округлено однаково).
Умова вимагає цілих чисел довільної довжини, тож `double` для неї не підходить.

### 2. Перерахунок лише залежних клітинок замість усієї таблиці

Таблиця 200 × 200, у кожній клітинці формула «попередня клітинка + 1»; змінюється A1.
Порівнюється підхід програми (граф залежностей, перераховуються лише залежні клітинки)
з простішим варіантом — перерахувати після зміни всю таблицю (як після відкриття файлу).
Медіана 15 вимірювань:

| Таблиця | Залежних від A1 | Лише залежні (програма) | Уся таблиця | Швидше |
|---|---|---|---|---|
| кожен рядок — окремий ланцюжок | 199 | 0,5–1 мс | ≈ 0,8 с | у сотні разів |
| уся таблиця — один ланцюжок | 39 999 | ≈ 130 мс | ≈ 0,8 с | ≈ 6 разів |

Навіть у найгіршому випадку, коли від A1 залежить уся таблиця, граф швидший: йому не треба
заново розбирати всі вирази й будувати залежності. Час залежить від комп'ютера, але співвідношення
зберігається; програма також перевіряє, що в обох підходах значення однакові.

## Використання генеративного штучного інтелекту

Відповідно до робочої програми дисципліни (рівень 2 використання генеративного ШІ)
декларую, що під час виконання роботи використовувався генеративний ШІ
**Claude (Anthropic)**:

- **Проєктування.** Пояснення вимог, обговорення архітектури та підготовка UML-діаграм.
- **Код.** Генерування варіантів програмної реалізації та unit-тестів.
- **Перевірка.** Аналіз та рецензування коду.

Отримані рішення критично перевірені й адаптовані мною. Я можу пояснити
структуру програми, призначення та роботу кожної її частини, обґрунтувати
прийняті рішення і модифікувати окремі фрагменти коду.
